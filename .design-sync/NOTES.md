# design-sync notes

- Badge: Inverse story's decorator wrapper renders full-bleed in the preview vs snug/centered in storybook -> storybook's meta-level `parameters.layout: "centered"` shrinks the canvas to fit content, which the preview harness doesn't replicate. Framing only — the component itself is pixel-identical. Not fixed, not actionable (harness framing difference, not a component defect).
- [GENERAL] `.ds-sync/storybook/http-serve.mjs`'s MIME table lacked `.svg` (and other non-html/js/css/json/png types), defaulting to `application/octet-stream` — Chromium refuses to decode `<img src="*.svg">` under that MIME type, so BOTH the storybook reference and the preview panel showed broken images identically, masking real fidelity. This is a bug in the skill's own shared script, not a per-repo issue (it isn't wired for `cfg.libOverrides`) — patched locally this run by adding `.svg`, `.jpg/.jpeg`, `.gif`, `.webp`, `.woff2/.woff`, `.otf`, `.ttf` to the MIME table. **This fix does not persist**: `.ds-sync/` is re-copied fresh from the skill's bundled scripts on every sync, so re-apply it (or check if a newer skill version has fixed it upstream) on the next sync if any component with an `<img src="*.svg">` shows broken images on both sides again.
- **Logotype shipped with a broken default asset path — fixed at the source, 2026-09-04.** `Logotype.tsx`'s default `src` was a relative path (`assets/logo/<variant>-<tone>.svg`) that the converter never had a mechanism to copy into the sync bundle (no generic static-image-asset knob exists — only `cfg.extraFonts`, which is font-specific). This wasn't just a preview artifact: any real design the agent built with bare `<Logotype />`, or with `SiteHeader`/`SiteFooter` (which embed it), would have rendered a broken image where the Lumenis mark should be.
- **Final fix (superseding an earlier data-URI attempt): `src` was removed from `Logotype` entirely.** It now imports all four real SVGs (`assets/logo/{wordmark,symbol}-{black,white}.svg`) directly (`import wordmarkBlack from "../../../assets/logo/wordmark-black.svg"`) and picks one via `tone`/`variant` — no override prop, no way to regress. This works because `lib/bundle.mjs`'s shared esbuild options already default `.svg`/`.png`/`.woff(2)` to the `dataurl` loader, and per `story-imports.mjs` rule 2, any import that resolves to an exported component (`Logotype` itself, or `SiteHeader`/`SiteFooter` which embed it) is shimmed straight to `window.<Global>` during preview/story compilation — so Logotype's own source, and its `.svg` imports, are never re-bundled there; only the main library build ever touches them, and it already had the right loader. Added `global.d.ts` at repo root (`declare module "*.svg" { const src: string; export default src }`) since `tsconfig.json` had no ambient type for image imports. `LogotypeProps` now uses `Omit<React.ImgHTMLAttributes<HTMLImageElement>, "src">` specifically so a caller can't accidentally pass `src` through `...rest` and shadow the fixed default — this bit a first draft of the fix (two OptiLIGHT ui_kit call sites still passed an explicit stale `src=`, which the type system didn't catch until the `Omit` was added). `SiteHeader`/`SiteFooter`'s `logoSrc` prop was removed to match; all three stories' `src`/`logoSrc` overrides were removed since they're unnecessary now; the owned previews created for the data-URI attempt (`.design-sync/previews/{Logotype,SiteHeader,SiteFooter}.tsx`) were deleted since the generated previews now render correctly on their own.

## Re-sync risks

- The `http-serve.mjs` MIME-table fix above is local-only and will need reapplying (or upstreaming) every sync until the skill itself ships the fix — if a future sync shows SVG-based components suddenly failing sb-error/broken-image on both sides, check this first before treating it as a real regression. Re-applied again this sync (2026-09-04); still not upstreamed.
- A repo commit (`017a9a1`, "Capitalize component group folders, retire per-component docs/cards") renamed all component group folders (`components/actions/` -> `components/Actions/`, etc.) between the previous sync and this one. The uploaded anchor's `sourceHashes` were keyed on the old lowercase paths, so this re-sync's diff treated **all 27 components as changed** (contract change via path, not real content change) and every grade had to be re-earned from fresh sheets. If group folders are renamed again, expect the same full re-grade cost.
- **Any component defaulting an `<img src="...">`/`background-image` to a bare relative or absolute path outside the bundle will silently break in every design the agent builds with it** — there's no `cfg.*` knob that copies arbitrary static image assets (only `cfg.extraFonts`, font-specific). The safe pattern (see `Logotype.tsx`): `import mark from "../../../assets/logo/foo.svg"` and use the imported value directly — `lib/bundle.mjs`'s shared esbuild options already default `.svg`/`.png`/`.woff(2)` to the `dataurl` loader, so this just works with zero converter changes, and it's cleaner than hand-computing a base64 string. Needs `global.d.ts`'s `declare module "*.svg"` (added this run) for `.tsx` imports to typecheck.
- **`conventions.md` references a `tokens/*.css` path that this build never actually ships** (this repo's storybook shape scrapes token definitions straight into `_ds_bundle.css` via `[CSS_FROM_STORYBOOK]` — there's no separate `tokens/` directory in the upload). The line "Read `styles.css` ... and the token files under `tokens/*.css`" should be corrected to drop the `tokens/*.css` clause (or point at `_ds_bundle.css`, already named earlier in the same sentence). Not fixed here per the skill's rule (author-owned file, existing conventions.md is never silently rewritten) — flagged to the user for a decision.
